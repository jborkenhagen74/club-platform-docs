# 아키텍처와 보안 모델

[언어별 시작 페이지](README.md) · [사용자 설명서](user-manual.md)

## 적용 범위

이 문서는 **Club Platform 0.5.0**, 구현 커밋
`320a4c2709c13dd56455768a2f8819a815ad3997`, 데이터베이스 스키마 8,
확장 ABI 2를 기준으로 합니다. 제품 버전, 마이그레이션 번호, ABI 번호는
서로 다른 계약입니다. 설명서가 다섯 언어로 제공되어도 현재 주로 독일어인
프로그램 화면이 모두 번역되었다는 뜻은 아닙니다.

프로그램은 사람, 조직, 회원 소속, 직책, 연락처, 파일과 종목별 데이터를
관리합니다. 한 사람은 여러 조직에 소속될 수 있습니다. 사용자 계정은 로그인
주체입니다. 사람을 등록해도 계정이 자동 생성되거나 현재 계정과 자동 연결되지
않습니다. 조직은 전국 연맹, 지역 연맹, 협회·클럽, 스포츠 학교, 기업 또는
기타 단체가 될 수 있습니다.

## 실행 방식

| 방식 | 화면 | 처리 및 저장 |
|---|---|---|
| 단일 PC | Qt Quick/QML | 로컬 호스트, SQLite, 공통 애플리케이션 서비스 |
| 서버 연결 데스크톱 | Qt Quick/QML | HTTPS REST, 서버가 데이터베이스 연결 소유 |
| 웹 포털 | React/TypeScript, Tailwind 4 | 정적 웹 파일과 C++ 서버 앞의 HTTPS 프록시 |

애플리케이션은 각 작업에서 세션과 권한을 확인합니다. 클라이언트는 작업자의
신원을 지정하지 않습니다. `actor` 또는 `actor_id`가 있는 REST 객체는
거부됩니다. 서버는 `127.0.0.1`에서 수신하며 TLS와 외부 접근은 역방향 프록시가
담당합니다. 클라이언트가 서버 데이터베이스에 직접 접속하면 안 됩니다.
SQLite와 PostgreSQL은 선택 가능한 저장소이며 자동 동기화되는 두 복제본이 아닙니다.

서버 연결 데스크톱에는 오프라인 쓰기 캐시가 없습니다. 포털 토큰은 메모리에만
보관하므로 페이지를 새로 고치면 다시 로그인해야 합니다. 브라우저에 지속적으로
저장하는 것은 화면 테마 선택뿐입니다.

## 데이터와 관계

레코드는 이름이나 회원번호와 별개인 UUID로 식별합니다. 수정할 때는 이전에
읽은 리비전을 함께 전송합니다. 충돌 검사는 다른 사용자의 변경을 덮어쓰는
일을 방지합니다. REST 리비전은 JavaScript의 큰 정수 반올림을 피하도록
십진수 **문자열**로 전송합니다.

개인 기록은 기본 신원, 개인 정보, 연락처, 주소, 관계, 회원 소속, 직책,
사용자 정의 필드와 파일을 한곳에 모읍니다. 회원 소속은 사람과 조직을 연결하고
부서와 회비 그룹을 추가로 지정할 수 있습니다. 회비 그룹은 기준 정보이며
자동 청구, 결제 또는 SEPA 출금 기능이 아닙니다.

상위 조직 필드는 전국 연맹 → 지역 연맹 → 스포츠 학교 같은 계층을 만듭니다.
추가 가입·협력 관계는 별도로 저장합니다. 계층은 사용자 권한을 부여하지 않으며
테넌트 또는 행 단위 보안 경계도 아닙니다. 상위 조직의 순환 연결은 거부됩니다.

사용자 정의 필드에는 정의, 자료형, 그룹별 권한과 값이 있습니다. 읽기와 쓰기는
별도 권한이며 쓰기만 허용된 사용자는 기존 값을 볼 수 없습니다. 자료형 변경은
모든 기존 값을 변환할 수 있어야 합니다. 하나라도 실패하면 전체 변경을 취소합니다.

## 인증과 권한

비밀번호는 Argon2id 해시로, 서버의 세션 토큰도 해시로 저장합니다. 기본 세션
최대 수명은 8시간, 비활동 제한은 30분입니다. 로그인 5회 실패 시 기본 30초
차단 구간이 적용됩니다. 클라이언트는 빠른 재시도 루프를 만들지 않아야 합니다.

권한 연결은 사용자 → 그룹 → 역할 → 권한 키입니다. 허용이 없으면 거부합니다.
`records.read/write`는 일반 레코드, `memberships.read/write`는 회원 소속과
직책에 사용합니다. `security.manage`는 계정과 시작 화면 이미지를,
`schema.manage`는 필드 정의, 문서 양식, 확장 설치를 관리합니다.
`audit.read`는 애플리케이션 API의 권한이며 0.5.0에 별도의 감사 HTTP 경로는
없습니다. `*`는 광범위한 관리자 권한입니다. 활성 관리자는 최소 한 명 남아야 합니다.

필드 권한은 일반 권한에 추가됩니다. 무술 데이터에는 `martial.read` 또는
`martial.write`도 필요합니다. 현재 버전은 계정을 자신의 사람·조직 레코드로
자동 제한하지 않습니다. 포털은 권한을 검사하는 관리 화면이며 완성된 회원
개인 셀프서비스 포털은 아닙니다.

## 파일, 트랜잭션과 한계

파일 내용은 데이터베이스에 저장되어 데이터베이스 백업에 포함됩니다.
일반 파일은 최대 5 MiB, 사진과 시작 화면 이미지는 서버에서 최대 2 MiB입니다.
화면은 PNG/JPEG를 축소하고 이미지 면적을 1,600만 픽셀로 제한합니다.
새 프로필 이미지는 해당 레코드의 기존 이미지를 교체합니다. 문서 업로드로
네이티브 모듈을 설치하지 않습니다.

변경과 감사 기록은 하나의 트랜잭션으로 처리합니다. SQLite는 쓰기를 직렬화하고
PostgreSQL은 해당 트랜잭션·잠금 기능을 사용합니다. 그러나 페이지별 CSV 내보내기는
특정 시점의 데이터베이스 스냅샷이 아닙니다.

범용 서명 설치 프로그램, 자동 업데이트 설치, 결제, 일정, 오프라인 동기화,
다중 테넌트 격리, 자동 문서 발송, 자유로운 확장 메뉴·REST 콜백을 완료된
기능으로 가정하지 마십시오. [버전과 범위](versioning.md)를 확인하십시오.
